# Previous Year Question Bank

A static, data-driven website: pick a subject, pick a lecture, see every past exam question for it (with figures,
tables and math), search by keyword, and jump around with a keyword sidebar.

Plain HTML + CSS + JavaScript (ES modules). **No build step, no npm.** KaTeX (math) and marked (Markdown) load from
a CDN, so the page needs an internet connection the first time.

> **The data in this folder is SAMPLE data** (13 made-up questions, placeholder lecture/keyword list for
> Theory of Computation). Every sample question text starts with `[SAMPLE QUESTION]`. Replace it with your own
> (see *Replace the sample data* below).

## Run locally

```bash
cd <this folder>
python -m http.server 8000      # or: python3 -m http.server 8000
# open http://localhost:8000
```

Opening `index.html` by double-click (`file://`) does **not** work: browsers block loading the JSON files that way.

## Folder layout

```
index.html, css/style.css, js/*.js     the site (nothing in here knows about specific questions)
data/subjects.json                     list of subjects
data/topics/toc.json                   lectures + keywords for a subject
data/questions/toc-<year>.json         per-year input files  (you edit these)
data/questions/toc.json                GENERATED by scripts/merge.py (the site reads only this)
images/toc/<year>/...                  figures (paths in the data are relative to the site root)
scripts/merge.py                       merges the per-year files, validates, prints a summary
```

## Add a new year (the common task)

1. Drop `toc-<year>.json` into `data/questions/` (e.g. `toc-2024.json`). Shape:
   `{ "subject": "toc", "exam": { ...one exam... }, "questions": [ ... ] }`
2. Put its figures in `images/toc/<year>/` and reference them in the data as
   `{ "src": "images/toc/2024/q3-pda.png", "alt": "PDA with states q0..q2 ..." }`.
3. Run `python scripts/merge.py`.
4. Refresh the browser.

To add or edit a single question, edit its per-year file and run the merge again. Never edit
`data/questions/toc.json` by hand: it is overwritten.

`merge.py` (Python standard library only):

- fails (exit code 1, writes nothing) on invalid JSON, a missing `exam` block, duplicate question ids or
  duplicate exam ids;
- writes `data/questions/toc.json` (exams newest first);
- makes sure `data/topics/toc.json` has **Lecture 9** "Undecidability & Complexity (not covered in slides)" with its
  ten topics (it only adds what is missing and never rewrites your other lectures);
- **warns** about keywords that are not in the topics file, figure files that do not exist, figures without
  `alt`, and marks that do not add up to 35 per question number (30 for 2020; grouped per exam + section + question
  number);
- prints questions per year and per lecture.

`python scripts/merge.py <subject-id>` merges another subject (Lecture 9 is only added for `toc`).

### Question fields

```json
{
  "id": "toc-2024-q3b", "exam_id": "toc-2024", "section": "B", "qno": 3, "part": "b",
  "marks": 15, "co": "CO4",
  "text": "Markdown with $inline$ and $$display$$ KaTeX math, tables and ``` code blocks.",
  "figures": [{ "src": "images/toc/2024/q3b.svg", "alt": "what the figure shows" }],
  "keywords": ["#CFGtoPDA", "#CFG"],
  "type": "conversion",
  "repeat_group": "cfg-to-pda",
  "needs_review": false, "review_note": "",
  "solution": "Optional solution with $inline$ math and Markdown."
}
```

- **Solutions:** Every question card features a `📚 Solution` option. You can view, add, or edit solutions directly in the browser with live Write/Preview tabs (supporting Markdown and KaTeX math). Solutions edited in the browser persist in `localStorage`. You can also supply a `"solution"` string directly in your per-year question JSON.
- Filter and toggle options: Use the **"Has solution"** filter to find questions with answers, and the **"Show solutions 📚"** toggle button to expand all solutions at once.
- **Save / Favorite & Archive:** Click the star icon (`☆` / `★`) on any question card to save it to your Favorites. The top-right **Archive** link opens your personal archive with dedicated lists for **Favorites**, **Solved**, and **Has Solution** questions, complete with revision statistics.
- Lecture numbers are **not** stored. A question appears in every lecture that one of its keywords belongs to.
- `part` can be `null`, `"b"` or `"(b)"`. `co` can be `null` (hidden), `"CO4"` or `4`.
- `type` is free text (`theory`, `design`, `conversion`, `proof`, `short-note`, or anything new); the type filter is
  built from whatever the data contains.
- Questions that share the same `repeat_group` string show "Asked N times (2019, 2021, 2023)" and are matched by
  the "Only repeated" filter.
- Keywords not found in the topics file still display (dashed chip) and are searchable; a warning is logged in the
  browser console and printed by `merge.py`. A question whose keywords are *all* unknown belongs to no lecture
  and can only be found through search (it gets a "No lecture" badge).
- `needs_review: true` shows a small "⚠ unverified" badge (with `review_note` expandable).
  Turn this off with `SHOW_REVIEW_FLAGS = false` in `js/config.js`.

## Add a new subject

1. Add an entry to `data/subjects.json`:
   ```json
   { "id": "dsa", "name": "Data Structures", "codes": ["CSE 1101"], "former_codes": [],
     "topics_file": "data/topics/dsa.json", "questions_file": "data/questions/dsa.json" }
   ```
2. Create `data/topics/dsa.json` (`{ "course": "...", "lectures": [ { "lecture": 1, "title": "...", "topics": [ { "keyword": "#Array", "name": "Arrays" } ] } ] }`).
3. Create per-year files `data/questions/dsa-<year>.json` (with `"subject": "dsa"`) and figures in `images/dsa/<year>/`.
4. Run `python scripts/merge.py dsa`.

The home page lists every subject in `subjects.json`; nothing else needs to change.

## Replace the sample data

Delete `data/questions/toc-20*.json`, `data/questions/toc.json` and `images/toc/*`, replace `data/topics/toc.json`
with your real lecture/keyword list (keep keywords starting with `#`), add your `toc-<year>.json` files and run
`python scripts/merge.py`.

## How the pages work

| URL | Page |
|---|---|
| `#/` | Subject cards (name, code, question count, year range) |
| `#/s/toc` | Search bar + lecture grid (lectures with 0 questions are dimmed) |
| `#/s/toc/l/5` | Lecture: keyword sidebar, filters, question cards |
| `#/s/toc/l/5?k=%23CNF&year=2021&type=proof&rep=1&hide=1&order=old` | Same, with filters (the URL updates as you filter, so any view can be shared) |
| `#/s/toc/search?q=cfg` | Search across the whole subject |
| `#/s/toc/archive` | Archive: Favorite questions, Solved questions, Has Solution list & stats |

- **Lecture sidebar:** click keywords to filter (multi-select, click again to deselect, "All keywords" to reset).
  The counts follow the current year / type / repeated / hide-solved filters. On phones it is a collapsible panel.
- **Default order:** newest year, then question number, then part. The button switches to oldest first.
- **Solved:** the checkbox is stored per question in your browser's `localStorage` (per device, not synced).
- **Figures:** click to zoom, Esc or click again to close.

### Search rules

- Case-insensitive; a leading `#` is ignored; several words must all match.
- Matches keywords (substring), topic names, question text (LaTeX markup stripped, so `\varepsilon` is found as
  "epsilon" but `mathbb` is not), and figure `alt` text.
- Ranking: keyword match > topic-name match > text match > figure alt match.
- `cfg` or `#CFG` matches every keyword containing "cfg" (`#CFGtoPDA`, `#CFGExamples`, ...) and shows them as
  "Matching keywords" chips; click a chip to narrow to that keyword, click again to widen.
- A query that is exactly one keyword **and no other keyword contains it as a substring** (e.g. `#CFGtoPDA`)
  returns only questions tagged with it. (If you type `#DFA` and you also have `#DFAMinimization`, both match;
  use the chip to narrow.)
- Typing on the search page updates results live (debounced). On other pages, typing shows keyword suggestions and
  Enter opens the search page. The index is built from the loaded data in the browser; there are no index files.

## Settings

`js/config.js`: `SHOW_REVIEW_FLAGS`, `SEARCH_DEBOUNCE_MS`, `PAGE_SIZE` (cards rendered per batch; the rest load on
"Show more" or when you scroll).

## Deploy

The folder is the site. Nothing to build.

- **GitHub Pages:** push to a repo, then Settings → Pages → deploy from the branch root. (`.nojekyll` is included.)
  Remember to run `python scripts/merge.py` and commit the generated `data/questions/toc.json`.
- **Netlify:** drag the folder onto app.netlify.com/drop, or connect the repo with no build command and `.` as the
  publish directory.
- Hash routing (`#/s/toc/l/5`) means deep links work on any static host without rewrite rules.

## Notes and choices

- CDN libraries are pinned: KaTeX 0.16.47 and marked 18.0.10 (jsDelivr). If a CDN is blocked the site still works
  but shows raw Markdown/LaTeX (a console warning says so). To self-host, download them and change the three tags in `index.html`.
- Question HTML is sanitised with an allow-list (no scripts, styles, iframes, images, forms; links must be
  `http(s)`, `mailto` or relative). Math is rendered by KaTeX (`trust: false`).
- Inline math uses `$...$`; a `$` followed by a space, or a closing `$` followed by a digit, is left alone so
  prices like "$5 and $6" stay text. Use `\$` for a literal dollar sign next to math.
- Data files are fetched with `cache: 'no-cache'`, so a plain refresh picks up changes after you re-run the merge.
- Everything is derived from the data at load time: years, types, lectures, keyword counts, repeat groups and the
  search index.
